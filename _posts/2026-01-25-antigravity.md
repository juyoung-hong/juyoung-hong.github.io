# 개요

요즘 바이브 코딩 도구가 점차 많아지고 있는 추세인거 같다.

최근 구글에서 출시한 anti-gravity가 무료로 제공하면서도 성능이 강력하다고 해서 한번 배워보고 사용해보려고 한다.

<br>

# 설치

Anti-gravity는 다음 [링크](https://antigravity.google/) 에서 다운로드 받을 수 있다.

우측 상단의 "Download" 페이지로 이동하여 각자의 환경에 맞는 설치 파일을 찾아 다운로드 하면 된다.

나의 경우 M1 맥북을 사용하고 있었으므로 Apple Silicon에 해당하는 파일을 다운로드 받고 설치하였다.

이후 코드 에디터의 설정과 구글 계정을 연동하는 부분이 나오는데, 일단은 default 옵션을 사용해서 모두 처리하였다.

<br>

# 에이전트 모드 설정

<br>

## 대화

에이전트와 대화할때는 2가지 모드가 존재한다.

- Planning: 작업을 진행하기전 계획하고, 조사하는 모드로 토큰을 많이 소비할 수 있으므로 복잡하고 어려운 작업을 수행할때 사용이 필요하다.
- Fast: 빠르게 완료할 수 있는 단순한 작업을 수행할때 사용하므로, 계획이 완료된 이후 계획에 맞추어 개발할때는 Fast모드를 사용하는 것이 좋을 것 같다.

<br>

## 정책

에이전트의 행동 정책은 아래와 같이 2가지가 존재하는데, 코파일럿을 사용해본 경험으로는 에이전트가 행동하기 전 사람이 검토하고 방향성을 잡아주는 것이 바이브 코딩에서는 중요하다는 생각이 들어, 나는 모든 부분에서 Request Review로 옵션을 설정하였다.

- Always Proceed: 검토 요청하지 않고 실행함
- Agent Decides: 에이전트가 검토 요청 시기를 결정함
- Request Review: 에이전트가 항상 검토를 요청함

<br>

## 규칙

에이전트가 따르도록 제약하는 문서이며, 전역 규칙을 설정하거나 워크스페이스별로 규칙을 정리할 수 있다.

사용자의 기술 스택, 스타일 등에 대한 제약 조건을 설정하며 12,000자 까지 작성이 가능하다.

<br>

### 전역 규칙

`~/.gemini/GEMINI.md` 에 위치하며, 모든 워크스페이스에 적용됨

<br>

### 워크스페이스 규칙

`.agent/rules` 에 위치하며, 규칙의 활성화 방식은 아래와 같은 방식이 있다.

- Manual: @멘션으로 규칙을 활성화하고 질문한다.
- Always On: 규칙이 항상 적용된다. (토큰 낭비가 될 수 있을 것으로 보임)
- Model Decision: 규칙에 대한 설명을 바탕으로 모델이 규칙의 적용 여부를 결정한다.
- Glob: 정의한 glob 패턴을 기반으로 패턴과 일치하는 모든 파일에 적용됨

Manual로 적용하는 것이 가장 정확하고 토큰을 낭비하지 않겠지만, 사용자가 항상 개입해야하며 귀찮은 부분이 있기 때문에 개인적으로는 프로젝트의 폴더 구조를 잘 잡았다면, Glob이 상당히 괜찮은 옵션이 될 수 있을 것 같다.

**규칙 멘션:** <br>
규칙파일내에서 `@filename`으로 다른 파일을 참조할 수 있으며, 규칙파일의 위치를 기준으로 상대경로로 참조하거나, 리포지토리를 기준으로 절대경로로 참조할 수 있다.
{: .notice--info}

<br>

## 워크 플로우

서비스 배포나 PR 코멘트 응답 등 반복적인 일련의 과정들에 대해 에이전트를 안내하는 단계를 정의할 수 있다.

저장된 워크플로우는 `/workflow`로 호출하여 사용할 수 있다.

마찬가지로 Global 또는 Workspace 단위로 생성할 수 있으며, 워크플로우 내에서 다른 워크플로우를 호출하도록 하려면 `Call /workflow-2`과 같은 지침을 포함하면 된다.

**에이전트 생성 워크플로우:** <br>
에이전트에게 워크플로우의 생성을 요청할 수도 있다.
{: .notice--info}

<br>

## 스킬

특정 유형의 작업을 진행하는 지침, 모범 사례, 컨벤션 및 사용할 수 있는 리소스로 에이전트는 사용가능한 스킬 목록을 확인하고 따름

에이전트에게 스킬을 사용하라고 명시적으로 말할 필요는 없으나, 명확하게 하고 싶다면 언급할 수 있음

- `~/.gemini/antigravity/skills/<skill-folder>/`: 전역 스킬
- `<workspace-root>/.agent/skills/<skill-folder>/`: 로컬 스킬 (팀의 배포 프로세스, 테스트 컨벤션에 적합)

<br>

### 스킬 폴더 구조

```bash
.agent/skills/my-skill/
├─── SKILL.md       # 메인 지침 (필수)
├─── scripts/       # 헬퍼 스크립트 (선택 사항)
├─── examples/      # 참조 구현 (선택 사항)
└─── resources/     # 템플릿 및 기타 자산 (선택 사항)
```

<br>

### Skill.md 파일 작성법

- 한가지 일만 할 수 있도록 분리된 작업에 대한 스킬을 작성해야함
- 명확하고 구체적으로 설명을 작성해야함
- 스킬에 스크립트가 포함된다면, 전체 소스코드를 읽도록하지 말고 --help와 함께 스크립트를 실행하도록 해야함
- 복잡한 스킬의 경우 상황에 따라 올바른 접근방식을 선택할 수 있는 섹션을 더해줘야함

```markdown
---
name: my-skill (소문자 사용)
description: 특정 작업을 돕습니다. X나 Y를 해야 할 때 사용하세요. (무엇을 하는지, 언제 사용하는지에 대한 명확한 설명)
---

# 나의 스킬 (My Skill)

에이전트를 위한 상세 지침이 여기에 들어갑니다.

## 언제 이 스킬을 사용하는가

- ...할 때 사용하세요
- 이것은 ...에 유용합니다

## 사용 방법

에이전트가 따라야 할 단계별 안내, 컨벤션, 패턴.
```

<br>

## 작업 그룹

에이전트가 계획 모드에 있을 때, 문제를 더 작은 단위로 분할하여 병렬 수행함

<br>

## 보안 모드

외부 리소스 및 민감한 작업에 대한 접근을 제한하게 할 수 있음

- 외부 웹사이트와의 상호작용: 허용목록, 차단목록으로 관리할 수 있음
- 터미널 사용: 검토 요청을 통해 명령 실행, 스크립트 실행, 아티팩트 접근을 검토하게 할 수 있음
- 파일 시스템 접근: 워크스페이스 외부의 파일은 접근하지 않으며, .gitignore에 정의된 파일을 접근하지 않음

<br>

## MCP

컨텍스트 (데이터베이스 스키마 또는 로그)를 필요할때 가져오도록 하여 제안의 근거로 삼을 수 있도록 할 수 있음

<br>

## 에이전트 매니저

에이전트 관리자는 여러개의 워크스페이스에서 동시에 작업을 수행할 수 있음

플레이그라운드를 이용하면 새로운 워크스페이스 생성없이 간편하게 대화할 수 있으며 작업 내용을 특정 워크스페이스로 옮길수도 있음

<br>

### Chrome 확장 프로그램

에이전트가 웹에 액세스 하도록 하려면 [Antigravity Browser Extension](https://chromewebstore.google.com/detail/antigravity-browser-exten/eeijfnjmjelapkebgockoeaadonbchdd?pli=1)를 설치해야함
